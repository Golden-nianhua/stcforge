# AiCube-ISP 6.97C 项目、发布和离线下载格式

地址对应 6.97C。本页描述主机生成和接收的数据。实物编程器执行这些数据的过程需要对应固件或实机证据。

## 硬件配置 `.cfg`

配置文件用 Windows INI 接口读写。菜单 `802D/802E/802F` 分别对应打开、保存、另存。读取从 `4B6C60` 进入，写入从 `4B7B10` 进入。`McuType` 保存型号名称，`Option` 经 `WritePrivateProfileStructA` 写入 16 字节原始选项，对应读取调用 `4B6E22`。程序还分别保存 `Frequency`、`McuPins`、`MinBaud`、`MaxBaud` 等字段。`Option` 是 Windows Profile Struct 格式，后续由 `44B760` 转成 ISP 的硬件选项包。

## 普通项目 `.stc`

`4B4B10` 为写入入口。`4B2A4C` 开始核对文件头并逐条读取。文件头为 `53 54 43 00`，其后连续存放如下记录。多字节长度为小端。

| 记录内偏移 | 长度 | 内容 |
| --- | ---: | --- |
| `0` | 1 | `70` |
| `1` | 1 | 记录类型 |
| `2` | 1 | 加法校验，使整条记录字节和的低 8 位为零 |
| `3` | 1 | 记录附加标志 |
| `4` | 4 | 主体长度 |
| `8` | 变长 | 主体数据 |

类型 `00` 且长度为零结束记录串。`4B6BA0` 构造并计算校验，`4B6C30` 单独更新校验。读取端在 `4B2AAC` 验证低八位，在 `4B3D38` 加 `8 + length` 前进。

6.97C 的写入和读取分支已经覆盖了从 01 到 25 的项目记录。

| 类型 | 主体长度 | 内容 |
| --- | --- | --- |
| 01 | 变长 | 项目标识、版本和文件名 |
| 02 | 4 | 保存时间 |
| 10 | 4 | MCU 型号值 |
| 11 | 16 | 原始硬件选项 |
| 12 | 4 | IRC 目标频率 |
| 13 | 0x54 | 主配置、用户系统区边界、程序区参数和相关开关 |
| 14 | 6 | RS485 接收、发送引脚和有效电平 |
| 15 | 1 | 本次下载的代码是否为加密代码 |
| 16 | 3 | 下载连接类型、端口和 USB 相关选项 |
| 17 | 变量 | 用户命令复位到 ISP 的启用状态、波特率和命令数据 |
| 18 | 变量 | 用户界面通信的启用状态、波特率和通信数据 |
| 19 | 变量 | 提示音和相关选择 |
| 1A | 变长 | 程序区自动增量名称 |
| 1B | 变长 | 数据区自动增量名称 |
| 1C | 0x11 | 离线编程器的电源、电流和下载设置 |
| 1D | 4 | 离线 ISP 频率覆盖值 |
| 1E | 4 | 自动增量起始值 |
| 1F | 4 | 自动增量步进值 |
| 20 | 0x28 | 自动增量配置页数据 |
| 21 | 4 | 自动增量信号参数 |
| 22 | 4 | 用户系统区或 EEPROM 参数 |
| 23 | 5 | 程序区边界和增量参数 |
| 24 | 变长 | 程序文件名及嵌入数据索引 |
| 25 | 变长 | EEPROM 或第二段代码文件名及嵌入数据索引 |
| F5–FB | 变长 | 发布项目需要的附加资源 |
| FC | 变长 | 发布权限、标题、串口配置和启动限制 |
| FD | 变长 | 用户密钥 |
| FE | 变长 | EEPROM 或第二段代码数据 |
| FF | 变长 | 程序代码数据 |
| 00 | 0 | 终止记录 |

13、17、18、20 和 23 的主体包含界面状态和内部结构，不能把它们当成单个整数。24、25 只有在对应文件或嵌入数据存在时才写入。F5–FC 只在发布流程中出现。完整读写指令保存在 [读取反汇编](project-read-6.97c.asm) 和 [写入反汇编](project-write-6.97c.asm)。程序告警 `2BDD` 说明普通保存省略密钥、下载口令和 ID 变换数据。

## 发布项目 `.exe`

1. `4BA931` 用与 `.stc` 相同的记录写入器生成临时文件。发布调用的参数开启额外记录。
2. `4BA9DE` 读取数据长度并向上对齐到四字节，`4BAA27` 用 `4E7F10` 处理整个数据块。资源类型 `RT_RCDATA`（`10`）、编号 `1`、语言 `0804`。`4BAA84` 调用 `UpdateResourceA` 写入。额外资源有独立的条件分支。
3. 程序读取发布文件时，在 `4B2964` 寻找此资源，随后复制出数据，`4B29C9` 调用 `4E7FC0` 逆变换，进入普通项目记录解析。

资源变换是带状态的字节置换，使用 EXE 固定的正反两张表。C 版表地址 `5373C8` 和 `5374C8`，资源的计数步进是 `1`。`.k` 密钥文件外层使用步进 `2`。用户固件加密用用户提供的置换表，和该资源封装是分别选择的功能。

[检查脚本](inspect-project.py)读取 `.stc` 或 6.97C 发布的 `.exe`，校验记录并列出偏移、类型、标志和长度。脚本直接读文件。记录校验、资源变换和逆变换已用离线 x86 执行对照，样本使用合成项目记录。

```powershell
$ispUv = 'D:/Code/uv/uv.exe'
& $ispUv run --project D:/Projects/stcforge --no-sync python inspect-project.py 'D:/path/to/project.stc'
& $ispUv run --project D:/Projects/stcforge --no-sync python inspect-project.py 'D:/path/to/release.exe'
```

## 离线编程器写入

菜单 `8070 → 4C6520 → 4D2B90` 启动模式 `4`。下载任务进入 `44E590` 的编程器分支。

| 阶段 | C 版地址 | 传输行为 |
| --- | --- | --- |
| 连接编程器 | `449120` | 查询编程器与外部 Flash 状态。无外部 Flash 时检查 `0xA800`（42 KiB）程序上限。 |
| 准备或传输第一段 | `449440` | 串口 `F1 00`，有数据时循环 `F2`，最后 `F3 C8`。`F2` 带三字节大端偏移，单块至多 128 字节。探针封装对应 `46`、`47`、`48`，单块至多 56 字节。 |
| 构造镜像 | `449800` | 前 `0x800` 字节为头部，程序从 `0x800` 开始，空白用 `FF` 补齐。 |
| 探针的额外准备 | `44A197…44A310` | 依次调用探针命令 `40`、`01`、`02`，等待各自应答。 |
| 传输离线镜像 | `44A36E…44A4D0` | 串口 `F4` 加三字节大端偏移及至多 128 字节数据，探针为 `49` 且数据至多 56 字节。每块检查应答，普通串口是 `F4 54`。 |

头部以 `5A A5` 开始。下表偏移以镜像起点为零，数值字段按大端存放。表中列出已确认的 F8D1 字段。

| 偏移 | 长度 | 字段 |
| --- | ---: | --- |
| `002` | 2 | `004..3FF` 的字节和低 16 位 |
| `004` | 2 | 程序覆盖范围的字节和低 16 位 |
| `006` | 4 | 原始程序长度 |
| `00C` | 2 | 主型号，F8D1 为 `F8 D1` |
| `00E` | 2 | F8D1 分支填 `型号 ^ 8000`，即 `78 D1` |
| `014` | 4 | 用户程序期望 IRC 频率，Hz |
| `018` | 4 | ISP 使用的频率，Hz |
| `020` | 16 | 原始硬件选项 |
| `030/031` | 各 1 | RS485 接收、发送控制引脚编码 |
| `033` | 1 | 型号选项组号，F8D1 为 `59` |
| `118/119` | 各 1 | 本次和下次下载口令长度 |
| `11A/15A` | 各 64 | 对应的口令缓冲区 |
| `19D` | 4 | 按 512 字节向下对齐后的程序覆盖起点 |
| `1B5` | 4 | 按 128 字节向上对齐后的程序覆盖结束位置 |
| `300` | 256 | 启用用户密钥更新时包含密钥数据 |
| `800` | 变长 | 程序区 |

用户密钥、口令、RS485、ID 和自动增量等选项会修改头部标志及覆盖范围。长度 260 的合成程序在 6.97C 原机器码内验证了头部、型号、两项校验、补齐与发送总长度，执行停在实际传输之前。源码位置见 [编程器反汇编](offline-6.97c.asm)。

模式 4 总是按 `4C3188/4C31A8` 选择辅助资源；COM 和编程器 HID 使用不同的资源变体。HID `48` 指令的长度位置填写 `C8`，但没有数据；HID 初始化返回的两个字节写入头部 `1A1..1A2`，随后重新计算头部校验。模式 5 清除已存任务：跳过 `F1/F2`，确认 `F3` 或 `48` 后，串口发送 `FF 08 20 36 C9`，HID `40` 的载荷为 `08 20 36 C9`。程序未等待清除命令的单独成功应答。

## `42` 辅助块和制作编程器

普通 USB HID 的另一辅助缓冲区属于模式 `7`「制作 Link1D/Writer1A/U8W 主控」。C 版 `4D2C4C` 启动该模式。任务选择内嵌固件资源并装入 `obj+6F0`，例如 `4C21D4` 装载 `res65.bin`，`4C2211` 解封、更新参数再封装。A 的 `44CCC4` 在模式 7 从相同逻辑缓冲区组包，命令基值 `42`，首块置 bit 5 成为 `62`，续块使用 `42`。这是主控制作的数据路径。普通离线用户程序使用模式 `4` 和前述 `F1` 到 `F4` 流程。

项目记录里尚需逐项命名的附加主体，以及离线镜像中仅由编程器固件解释的字段，均保留在反汇编供后续交叉核对。没有发布实物样本或编程器返回包时，验证范围到主机的序列化与传输调用为止。

## 发布 EXE 的用途和资源

发布 EXE 面向最终使用者。它把下载程序、项目配置和可选的固件数据封装在一个可直接运行的 EXE 中，用户无需打开 AiCube-ISP 或读取 stc 文件即可执行升级。对 CLion 和 stcgal 的下载流程没有依赖。

6.97C 的发布程序模板保存在资源 184 中。启动时从 0x566068 取出四个初始字，分别按按位取反后加上 0x310068、0x230033、0x330021、0x390031，生成 16 字节内部密钥。资源 184 是一个 ZIP，ZIP 内的 res*.bin 条目使用该密钥的 ZipCrypto 数据区。每个条目的前 12 字节是 ZipCrypto 头，后面按条目的压缩方式解压。已从 6.97C 原文件解出 93 个资源到 resources 文件夹。res17.bin 是发布程序基础 EXE，res65.bin 是一个未压缩的辅助数据条目。
