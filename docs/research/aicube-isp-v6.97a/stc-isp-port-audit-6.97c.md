# AiCube 6.97C → stc-isp 实现审计

`models-6.97c.json` 的 1345 条型号记录和 85 个配置族来自 AiCube 的型号表与界面分发。它们不是 1345 条已实现的下载流程。C++ 的实际写入入口集中在 `isp_route()`；命令行列出的能力、离线校验和联机发送都用同一个判定。

| AiCube UART 原始选择器 | 型号记录 | stc-isp 已接入的 UART 写入 |
| ---: | ---: | --- |
| 0 | 136 | 136：STC89、STC90、STC12，含 BSL ≥ 7.2 升级分支 |
| 1 | 542 | 542：STC89C51/C54、STC10/11/12 及对应别名，含 BSL ≥ 7.2 升级分支 |
| 2 | 6 | 6：STC15E/EA BSL ≥ 6.0，支持混合 EEPROM 镜像 |
| 3 | 637 | 632：新增 202 条 STC15、27 条 AI/STC32G12、G8、F12 和两条 AI/STC16 Beta |
| 4 | 24 | 24：IRC15 程序区；不改硬件配置 |

当前合计 **1340 条 UART**。BSL ≥ 7.2 时，AiCube 会将原始选择器 0–2 升为 5；原始选择器仍决定 128 或 64 字节的数据块上限。表中的数字是目录记录数（含别名），不等于实板验证数量。原生 USB 已接入 **67 条**，包括配置族 70、76 和 84 的新增 MCU 路径。Link1D HID-UART 和普通串口共用目标侧 UART 流程，探针自动供电只是连接和握手方式，不增加型号兼容性。

型号表中 71 条记录带原生 USB 标志 `0x4000`（`0x4BDDA0`）；另有应用侧硬件选项 `0678`（下次启用 USB-ISP），两者不可混用。其中四条工具身份走 `--make-tool`，不套用 67 条普通原生 USB 下载路线。

## 旧 STC15 软件 USB：重写配置与口令校验

旧实现会在擦除前检查握手状态第 12 字节：bit 2 为 `0` 表示 ISP RS485 已启用，BSL 7.2 起 bit 3 为 `0` 表示下载口令已启用。这些位只报告启用状态，不提供原有的方向引脚、电平或口令。拒绝重写是 `stc-isp` 为避免覆盖旧设置加的保护，不是 BSL 要求。

AiCube 6.97C 软件 USB 路径按本次设置组包（`0x44B760`、`0x44BA6A`），写完程序后发送 `04`（`0x44DFB7`、`0x44E022`），不以旧启用状态阻止重写。`stc-isp` 在该路径采用同一策略：启用硬件配置写入时，未在本次请求中设置的 ISP RS485 和下次口令可能被关闭；不想覆盖硬件配置时用 `modify_hardware_options=false`。当前下载口令仍通过 `05` 校验，收到 `0E` 或 `0F` 会在擦除前终止；回包长度检查和 UART 的保留检查不变。

## 仍未完成的移植

- 工具设备：USB-2UART（`F78F`）已接入 USB 写入；新工具主控的原生 HID 制作和旧工具主控的串口制作已接入。运行中工具自身升级仍未移植。
- 软件 USB（`5354:4312`）：`0x44C190/0x44C2F0` 的控制传输、`0x44D7F0` 的基础擦写、密钥、UID 名单及绑定、测试参数和部分 8 位配置已接入；不套用原生 HID。其他旧版配置体和扩展地址仍未接入。
- 旧 BSL：选择器 2、旧 STC15 选择器 3 低于 6.0，原生 USB 低于各路径的版本下限，以及两款 IRC15x207A 之外的选择器 4 低于当前 6.6 下限。不能把程序写入覆盖等同于硬件配置覆盖。
- 仿真制作：型号、模式和代表报文已离线核对，未逐型号实机验证。握手状态不足以还原已启用的 ISP RS485 方向设置时，配置式制作在擦除前停止。
- 离线编程器：普通镜像、UID 绑定、程序/EEPROM 自动增量、型号辅助资源、串口/HID 上传和模式 5 已接入；用户系统区策略、分口供电和编程器固件升级未接入。
- 其他功能：更老的串口 IRC 算法和完整的硬件状态解码仍有缺口。旧 STC12 的 EEPROM 填充已接入，不等于支持旧设备的所有独立 EEPROM 操作。
- 配置：型号模板是原程序界面选项的目录，不能视为写入覆盖。剩余工作包括未接入的字段和旧 BSL 配置包。表中的复现结果来自原始 x86 例程与模拟传输。
