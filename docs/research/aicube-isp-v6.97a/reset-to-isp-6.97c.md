# 收到用户命令后复位到 ISP 监控程序区

这条功能已经在 6.97C 主机代码中完整定位。它分为应用侧命令解析、应用侧 HID/串口写出、等待应用跳转 ISP 和正式 ISP 下载四步。

## 调用链

```text
下载任务 0x4C0250
  ├─ 读取项目中的用户命令复位配置
  ├─ 解析命令文本或 HEX 数据 0x4A92C0
  ├─ 应用侧 HID 写出 0x4C0997
  ├─ 或应用侧 COM 写出 0x4C0C25
  ├─ 等待并关闭应用侧设备
  └─ 重新进入 ISP 传输选择
       ├─ 0x44D7F0
       ├─ 0x44C800
       └─ 0x44E590
```

项目格式中记录类型 `0x11` 保存这部分配置，包括启用状态、通信参数和命令数据。项目读取代码在 `0x4B...` 路径中恢复这些字段，下载任务在 `0x4C0250` 使用它们。

## 命令解析

`0x4A92C0` 同时支持两类输入。

- 文本形式经过字符串转换后逐字节复制。
- HEX 形式按十六进制解析成字节数组。
- 调用者把长度限制为 `0x20` 字节。
- HID 和串口写出前都会重新调用该函数获取长度和数据。

解析函数自身负责分配、复制和释放临时缓冲区，返回实际字节数。调用者不会把文本的结束零字节作为命令发送。

## 应用侧 HID

6.97C 的 HID 写出路径位于 `0x4C0C39` 至 `0x4C0CC5`，实际写入点是 `0x4C0997` 的 `WriteFile` 调用。

| 项目 | 静态结果 |
| --- | --- |
| 设备打开 | 通过 `0x4E92A0` 根据配置的设备标识打开应用侧 HID |
| 报告长度 | `0x41` 字节，也就是 65 字节 |
| 第 0 字节 | 报告 ID `0x00` |
| 后续数据 | 用户命令，最多 32 字节 |
| 其余字节 | 保持零填充 |
| 写出 | `WriteFile` |
| 写出后等待 | `Sleep(0x32)`，即 50 ms |
| 结束 | `CloseHandle`，随后回到下载任务 |

代码中同时存在应用侧设备标识的配置读取路径。固定的 `0x34BFFF0F` 和 `0x34BFFF09` 是默认打开路径的参数，不应当当作所有应用固件都必须使用的 VID/PID。用户配置的设备标识会通过同一打开辅助函数传入。

## 应用侧串口

串口写出路径位于 `0x4C0AA3` 至 `0x4C0C33`，实际写入点是 `0x4C0C25` 的 `WriteFile` 调用。

| 项目 | 静态结果 |
| --- | --- |
| 端口打开 | `CreateFileA`，以读写方式打开项目指定的 COM 设备 |
| 串口配置 | `GetCommState`，再根据项目中的波特率、校验、停止位和 DTR/RTS 修改 DCB |
| 数据位 | 代码固定设置为 8 位 |
| 命令长度 | 最多 32 字节 |
| 写出 | `WriteFile`，直接写命令字节 |
| 写出后等待 | `Sleep(0x32)`，即 50 ms |
| 结束 | `CloseHandle` |

代码通过 `0x4E94AC` 读取项目中的串口参数，再通过 `SetCommState` 写回 DCB。DTR 和 RTS 分别由项目字段转换后写入控制位。

## 与 ISP 下载的衔接

应用侧命令写出完成后，主任务继续执行到连接模式分支。连接模式值为 1 时调用 `0x44D7F0`，值为 2 时调用 `0x44C800`，其他值调用 `0x44E590`。因此应用侧复位命令和后续 ISP 传输是两个独立层次。

应用固件收到命令后是否跳转到 ISP、是否要求重新枚举 USB、是否检查 P3.2/P3.3，由芯片应用程序和型号功能决定。主机侧已经把命令构造、设备打开、写出、等待、关闭和后续 ISP 入口全部逆出。
