# AiCube-ISP 6.97C 串口 IRC 动态调节静态分支

串口 IRC 总入口是 `0x4413F0`。它根据型号族、硬件选项和已经解析的状态值选择静态预置、USB 风格选择函数，或者进入动态测量流程。整个分支来自 6.97C 主程序，不需要逐型号抓包才能建立映射。

## 入口分支

| 条件 | 调用 | 处理 |
| --- | ---: | --- |
| `flags & 0x7F8000 < 0xC8000` | 直接结束 | 该族不进入这套动态调节 |
| 对象 `+0x22` 非零 | `0x43E9E0` | 使用已有状态或预置参数 |
| 选项缓冲区 `opt[0x0F]` bit 7 未置位 | 直接结束 | 本次不修改硬件选项 |
| `opt[0x0F] & 0x60 == 0x20` | `0x43E9E0` | 沿用上一次调节的频率，复制状态包中的已有修调值 |
| `opt[0x0F] & 0x60 == 0x40` | `0x43EFC0` | 使用内部预置频率，按内置频率表选择和设置 |
| 其他情况 | 本函数继续 | 进入串口动态测量 |

动态流程先等待 10 ms，记录 `GetTickCount()`，再按型号标志选择修调实现。

## 型号族到动态修调函数

| `flags & 0x7F8000` | 调用 | 说明 |
| --- | ---: | --- |
| `0xC8000` 或 `0xE0000` | `0x43F140` | 低容量老族动态修调 |
| `0x168000`、`0x170000`、`0x178000`、`0x180000`、`0x188000`、`0x190000`、`0x198000`、`0x1A0000` | `0x4402F0` | 旧布局型号族动态修调 |
| 大于等于 `0x1A8000` | `0x4413D0` | 按 BSL 版本选择 `0x4407C0` 或 `0x440CE0` |
| 其他情况 | `0x43F920` | 四频段粗测，随后分别测量程序与 ISP 换速所需的修调参数 |

## 动态流程中的固定参数

`0x4415C0` 之后建立发送缓冲区，使用型号记录中的识别码低字节和高字节，发送参数包括：

- 命令长度 7
- 固定字节 `0x50`
- 型号识别码低字节
- 固定字段 `0x36`
- 固定字段 `0x01`
- 等待参数 `0x1388`

随后调用 `0x43D0D0`、`0x43D4B0` 和 `0x43D240`，通过串口读取测量结果。对象成员 `+0x23` 控制继续测量，`+0x25` 和 `+0x1C8` 参与成功返回条件。

## 候选周期常量

`0x4416C0` 初始化动态调节使用的候选周期表。表内常量为：

```text
0xE1000, 0x70800, 0x38400, 0x1C200, 0xE100,
0x9600, 0x7080, 0x4B00, 0x3840, 0x2580,
0x12C0, 0x960, 0x4B0
```

选项或状态允许用户输入频率时，程序把对象 `+0xE8` 限制到这组范围。动态修调函数使用对象 `+0x118` 和 `+0xF8` 计算误差，最终写入对象 `+0x1E8`，并将对象 `+0x36` 置为 1 表示完成动态过程。

## 静态预置与动态调节的关系

主程序确实把两者分成不同分支。USB 路径可以直接从状态和内嵌频率表计算写入参数，串口路径在满足选项条件时才执行测量、等待和候选选择。这个差异来自 `0x4413F0` 的分支代码，不需要通过逐型号实测才能确认。
