# Link1D 联机 ISP：检测、下载、仿真制作和供电

依据本机 `AiCube-ISP-v6.97C.exe`，SHA-256 `D857B147F2F4E527C5566A2DD40E63F875C94F4E344FA5CE800AB13A770DB420`。下文地址是 PE 虚拟地址。结论来自主机静态分析和 Windows 设备枚举，未向实板发送命令，也未验证 S‑VCC 的电压波形。

## 传输路径

| 主机接口 | 目标芯片接口 | 区别 |
| --- | --- | --- |
| 目标芯片 USB HID `34BF:1001` | 芯片自身 USB ISP | 当前 `stc-isp --if usb` |
| 系统 COM 口，含 Link1D 虚拟串口 | UART ISP | 当前 `stc-isp --if serial --port …`；不会因此获得 Link1D HID 的供电控制 |
| Link1D HID `34BF:1004` 或 `34BF:1005` | UART ISP | AiCube 的 `(Link…) USB-HID-UART1`，对应 `stc-isp --if link1d` |
| Link1D HID 的调试命令 | SWD | STCForge 已有的调试传输；不是这条 UART ISP |

本机枚举到 `34BF:1005` 的 `MI_00` HID，以及独立的 `MI_01`、`MI_03` 虚拟串口。`4AFF9D`、`4B0023` 按两个产品号枚举，显示名来自 `566458`。`4BC298` 的跳转表把两者映射到端口类型 `4`（`4BC073`）。下载线程的 `44E602..44E69B` 设置 Link1D 类标记 `obj+25`，走 HID 打开函数 `44BCA0`，不走 `44E680` 的 COM 文件名分支。AiCube 内置帮助另将该端口写作 `-port=Link1D`，与 `-port=HID`（目标原生 USB ISP）区分。

## 自动断电和上电

**AiCube 发起，Link1D 控制 S‑VCC 并执行目标 UART 握手。** 不是插上探针就自动重启目标；也不是 AiCube 通过普通 COM 的 DTR/RTS 来完成这条路径。

- `43DD1D..43DD81` 先向 Link1D 发工具命令 `00`，读工具响应。
- `43DEDA` 准备 UART 波特率，`43DEE1` 给 Link1D 下发 `40` 的设置子命令，随后 `43DF9F..43DFA7` 向工具写 `41`，载荷是 8 字节，来自另一工具分支九字节 `F8 …` 请求去掉 `F8` 后的字段。主机紧接着进入 HID 读取等待；这一分支不在 PC 侧循环向 COM 写 `7F`。界面的上电延时、S‑VCC 输出电压和电流设置是工具侧设置，不能当成目标芯片的 `04` 硬件选项，也不能把主机等待应答的超时当成掉电时长。
- 完成时，`44F587` 调用 `43D990(1)`。这个函数通过工具命令 `40` 下发结束状态和恢复设置：可见子命令 `04` 带参数 `1`，部分路径有 `0C`、`00`、`03/05`、`0A`，最后 `43DC44` 发送工具命令 `FF`。异常收尾处 `44FA3A` 改用 `43D990(0)`，不能按成功路径处理。界面 `0640` 是“在线下载完成后持续给目标芯片供电”（`4C1092..4C10AA` 读入），默认勾选见 `4D2A16`。
- 工具只能切换它控制的供电。目标如独立供电，不能假设 S‑VCC 切换就使目标掉电；AiCube 自带提示 `529A` 也要求检查独立供电是否实际断开后重新上电。`41` 的逐字节电气参数和不同模式下的实际波形尚未实测。

## HID 封装

`44C050` 输出 65 字节，包含 Windows HID Report ID 槽；其余空位补零。下列偏移包含该槽。

| 偏移 | 内容 |
| --- | --- |
| 0 | Report ID `00` |
| 1 | `5A` |
| 2 | 工具命令 |
| 3–6 | 32 位参数，大端 |
| 7 | 附加数据长度 |
| 8 起 | 附加数据，最多 56 字节 |
| 64 | `(-sum(report[0:64])) & 0xFF` |

`43D0D0` 把**一条目标 ISP 载荷**交给工具：长度小于 56 字节使用 `43`；长度达到 56 字节时用 `44` 按最多 56 字节分片，32 位参数为从零起的片偏移，最后发 `45` 提交。这些是 Link1D 命令，不能作为目标 ISP 命令直接写到 UART。

`44BEF0` 用 `ReadFile` 读取 65 字节 HID 输入报告，并取偏移 2 为工具状态、偏移 3 为目标应答长度，数据从偏移 4 开始。调用者分别判断工具状态和目标应答。这个入口不经过普通 COM 的 `46 B9 68` 帧解析器，也不经过原生 USB ISP 的 `44BCE0` 解析器。

## 三种任务

| 任务 | AiCube 6.97C 的主机路径 |
| --- | --- |
| 检测 | 模式 `1`。`43DCD0` 完成工具和目标握手，`43E1F0` 解析目标型号与选项；`43E644` 在模式 `1` 提前结束，未进入擦除和写入阶段。检测仍会经过工具的供电流程。 |
| 普通下载 | 模式 `2`。走相同握手；STC32G144K246 的串口分支经 `44F0C3` 完成速度切换相关阶段，`44F0D8 → 4428D0` 擦除，`44F26B → 443240` 发送程序，按选项进入 `4439D0` 写配置。动态 IRC 校准仍由 UART ISP 的型号与选项分支决定。 |
| 制作仿真芯片 | 控件 `0768` 选中走模式 `8`（SWD），否则走模式 `6`（非 SWD，具体是否可选由型号决定）。端口类型 `4` 未被 `4BB740` 拒绝。制作使用上面的 UART ISP 路径；制作完成后才切换到所选仿真接口调试。 |

仿真任务在 `4C2289..4C2295` 进入独立的辅助数据准备路径，在 `44F2C4..44F2F0` 以命令基值 `42` 调用发送函数。**这不表示 STC32G144K246 必须写一份额外的监控 HEX**：其 `F8D1` 型号走 `4C2559..4C2620` 的通用分支，该分支把辅助数据长度置零，跳过型号专属的资源拼接，`4C26EA` 保存的发送长度仍为零。实际启用由配置路径完成：SWD 模式下 `44B99D..44B9A6` 清 `04` 载荷偏移 39 的 bit 5，bit 7:6 保留所选引脚对；非 SWD 的模式 `6` 修改的是偏移 43 的 bit 7。详细布局见 [F8D1 硬件选项](f8d1-hardware-6.97c.md)。该结论不外推到有专用监控资源的其他型号。

## 接入 STCForge

Link1D 作为独立的 `--if link1d` 传输，沿用目标 UART ISP 的状态解析和下载逻辑，独立处理工具枚举、HID 命令、分片、握手和供电收尾。`--link1d-auto-power false` 改用 UART1 虚拟串口和手动上电。它不改变目标协议族的覆盖范围；实现状态和 CLI 示例见 [stc-isp 使用说明](../../stc-isp.md)。首次实机验证应从检测开始，核对工具状态、目标型号及 S‑VCC 行为，再验证普通下载和制作 SWD 仿真芯片。
