## 收到用户命令后复位到 ISP

主机可以手动发命令，也可在下载任务开始时先发。界面可选应用侧 HID 或 COM 设备，命令支持 HEX 和带转义的文本，写出上限为 32 字节。

- HID 以配置的 VID/PID 打开正在运行的应用设备，写入 65 字节 Windows 报告缓冲区。第 0 字节是报告 ID `00`，后接命令，其余补零。两版写入点为 `4BFC81` / `4C0997`。
- COM 使用界面选定的波特率、校验、停止位，数据位为 8，DTR 与 RTS 可分别配置。直接写命令字节，约 50 ms 后关闭端口。两版写入点为 `4BFF0F` / `4C0C25`。
- 应用固件收到自己约定的命令后跳入 ISP，例如识别 `@STCISP#` 后写 `IAP_CONTR = 0x60`。手册印刷第 244–245 页给出了软复位进入 ISP 及 `RSTFLAG.2` 对 P3.2 条件的影响。随后主机按「下次使用 HID 下载」等连接选择进入正式握手。原生 USB ISP 枚举 `34BF:1001`，应用侧 HID 使用其自身的 VID/PID。 [STC 不停电下载说明](https://www.stcaimcu.com/forum.php?mod=viewthread&tid=159)

当前 stcgal 的 USB HID 后端没有上述应用侧发命令流程。移植时应分别读取应用侧传输参数和复位后的 ISP 连接方式。

## `04` 硬件选项补充

F8D1 常规配置载荷总长 46 字节，前 5 字节是 `04 00 00 5A A5`。下表从命令字按零编号。`opt` 是宿主程序的原始选项缓冲区。振荡器、低压复位、上电看门狗、P3.2/P3.3、EEPROM 和用户系统区等已有抓包支持的字段在 [原分析](../../../stcgal/doc/zh_CN/AiCube-ISP-6.97A.md) 中列出。

| 偏移 | 补充结果 |
| --- | --- |
| 8、11 | RS485 收、发方向控制电平分别落在 bit 4。高电平有效时置位，低电平有效时清零。 |
| 9、12 | RS485 收、发方向控制引脚编码，取自对应下拉框条目的数据字段。 |
| 26、36 | 分别来自 `opt[10]`、`opt[13]`，F8D1 常规界面采集保持 `FF`。 |
| 27 | 下一次下载口令长度。与本次用来解锁的口令分开。 |
| 29–35 | 频率、修调、频段、分频。原生 USB 按 `00` 状态和预置基频组包。两版预置表位于 `519CC0` / `51AD08`。 |
| 37 bit 2 | 清零启用目标芯片下次下载使用 RS485 控制。界面的「本次使用 RS485 进行控制下载」另有主机侧标志。 |
| 37 bit 3 | 启用下载口令并提供非空下一次口令时清零。 |
| 37 bit 4 | 勾选「下次下载时使能 USB-ISP 模式」时置位。 |
| 37 bit 5 | 清零请求用户代码区校验和，状态显示分支还会读取并显示相应值。 |
| 39 bit 7:5 | bit 7:6 选择 SWD 引脚对，模式 8 清零 bit 5。 |
| 39 bit 0 | 勾选「禁用 EEPROM 功能」时置位。 |
| 40 bit 7:5 | bit 7:6 选择串口仿真引脚对，bit 5 来自界面的 USB 仿真开关。 |
| 41 bit 6 | UART1 切换到 `P3.6/P3.7`。 |
| 43 bit 6 | CPU 指令模式。`0` 二进制模式，`1` 源码模式。 |
| 43 bit 7 | 模式 6 清零启用 USB-ICE。 |

验证脚本遍历 19 个选项字节的单独置位，并改变下载模式与下一次口令长度。两版 41 字节组包函数输出在 412 组输入中全部相同。普通、USB-ICE 和 SWD 三种模式下的差别只有上表两处模式位。此结果校验了组包函数，字段的界面含义和设备行为需结合对应分支、抓包核对。

RS485 共用设置页在两版 `412550` 先插入「高电平有效」再插入「低电平有效」。C 版从 `4C0F72` 读取启用控件、选定极性及引脚数据。两版 `411FE0` 的 62 项选脚表完全相同。每组按引脚号顺序编码，P0 为 `80–87`，P1 为 `90–97`，P2 为 `A0–A7`，P3.2–P3.7 为 `B2–B7`，P4 为 `C0–C7`，P5 为 `C8–CF`，P6 为 `E8–EF`，P7 为 `F8–FF`。这是共用页面的可选项，F8D1 对每个选脚的实际支持范围待验。

## 下载口令、密钥和加密

- **下载口令**。启用时，`05` 准备命令带当前口令。6.97A 的 `44C890` 识别准备阶段的口令错误提示。新口令由 `04` 中的标志和长度预告，随后通过 `07` 写入，预期确认 `07 54`。界面分别保存 `Password1`、`Password2`，下载对象限制各 63 字节。
- **用户密钥更新**。`26` 承载 256 字节用户密钥，按 64 字节分四块发送。6.97A 的明文密钥表生成、`.k` 封装、导入分别可从 `45B690`、`45BD4D`、`45B890` 追到。密钥文件和程序文件各有自己的变换。
- **固件文件加密**。主机例程使用 256 字节置换表及其逆表，逐字节推进状态。两版正向与逆向函数各自的机器码相同。验证脚本用五组长度为 1、16、256、512、1024 字节的合成数据，把原函数输出与 Python 复算结果逐字节比较，并检查往返一致。下载页的「本次下载的代码为加密代码」另有标志，已跟到初始化和 EEPROM 写块的条件分支。芯片何时解密、保存何种形式，以及各 BSL 对流程的限制仍待确认。
- **芯片 ID 绑定**。擦除应答提供 7 字节芯片 ID。6.97A 的 `4423A0` 负责名单检查，`442400` 负责变换，至多生成两份供写入镜像指定地址的数据。每份可按配置对各个 ID 字节应用至多四个算术操作。应用到 F8D1 的实际写入条件和芯片上读出结果仍待验。
