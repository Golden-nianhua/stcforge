这份文件定义当前逆向结果的边界，方便后续重构时按模块搬运。地址均为 32 位 PE 虚拟地址，镜像基址为 `0x00400000`。

完整字段和每一条型号记录见 [models-6.97c.md](models-6.97c.md)，程序使用 [models-6.97c.json](models-6.97c.json)。

型号族下载资源的选择关系见 [resource-routes-6.97c.md](resource-routes-6.97c.md)，已解出资源的大小和 SHA-256 见 [resources-6.97c.md](resources-6.97c.md)。

`models-6.97c.json` 中的 `config_layout` 是根据 `0x44B760` 的静态比较得到的载荷分支分类。它记录了 `legacy-0x40`、`extended-0x28` 和 `extended-0x29` 三种返回长度，以及 `byte_27`、`0x260000`、`0x2C8000` 和旧 BSL `0x1E8000` 的特殊分支。它描述的是主机组包函数的路径，具体字节仍要结合型号族的选项表和设备应答校验。

同一数据库的 `status_layout` 根据 `0x43E1F0` 的型号标志分支计算状态块大小。6.97C 的 85 个型号族中，22 个族进入 `0x80` 字节状态块路径，63 个族进入 `0x40` 字节状态块路径。这个分类完全来自主程序比较指令，不需要逐型号上电验证。

下载任务在 `0x4C2BA1` 读取连接模式并选择主传输入口：

| 连接模式值 | 调用入口 | 作用 |
| ---: | ---: | --- |
| 1 | `0x44D7F0` | USB 下载封装 |
| 2 | `0x44C800` | 原生 USB HID 下载 |
| 其他值 | `0x44E590` | 串口或转接器下载 |

这个选择位于型号族分支之后，型号族主要负责选项描述、资源准备和配置载荷格式。重构时应把「型号协议族」和「连接传输后端」做成两层数据，而不是为每个型号复制一套下载流程。

用户命令复位的完整静态路径见 [reset-to-isp-6.97c.md](reset-to-isp-6.97c.md)。6.97C 已确认应用侧 HID 的 65 字节报告、应用侧串口最多 32 字节写出、串口 DCB 参数、50 ms 等待、关闭设备，以及复位后重新进入 ISP 传输选择。

## 配置族与传输方式的关系

配置族决定硬件选项描述、配置载荷字段和资源准备分支。USB HID、串口和转接器的主传输选择由下载页面的连接模式决定，不能仅凭型号族编号推断。当前已经把每个型号族的资源准备分支记录在型号 JSON 的 `asset_route` 中，方便继续追到对应调用者。

硬件配置函数 `0x44B760` 中已确认的分支条件包括：

- `flags & 0x7F8000` 在 `0x168000` 至 `0x1A0000` 的若干族使用一套 0x40 字节布局。
- 小于 `0x1A8000` 的族进入另一套旧布局。
- 大于等于 `0x1A8000` 的族进入新布局，常规返回长度为 `0x28`。
- `0x2C0000` 和 `0x2C8000` 族会追加第 `0x28` 字节，返回长度为 `0x29`。
- `0x2A0000`、`0x260000` 等族还会改变频率分频和校准字段的变换方式。
- 连接模式会额外影响仿真、SWD、USB-ISP 和校验相关位，属于任务状态输入，不是型号记录本身的固定字段。

F8D1 和 8H8K USB 族已经有抓包或本地静态验证。其余族目前已完成分支和描述表提取，设备端字节含义需要用对应型号的抓包或实板验证后再写进重构代码。

## 逆向脚本

运行下面的命令可以从原始 6.97C 文件重新生成型号目录。

```powershell
$research = 'D:/Projects/stcforge/docs/research/aicube-isp-v6.97a'
$uv = 'D:/Code/uv/uv.exe'
& $uv run --project D:/Projects/stcforge --no-sync python `
  "$research/extract-models-6.97c.py" `
  --json "$research/models-6.97c.json" `
  --markdown "$research/models-6.97c.md"
```

脚本会校验 6.97C 的 SHA-256，避免把其他版本误当成当前样本。它只读取 PE 文件，不启动 AiCube-ISP，也不连接单片机。
