# STC USB-ICE 实现依据

本项目使用用户抓取的 STC32G144K246 官方 USB 仿真会话，辅以 Keil 驱动静态分析。
协议没有官方公开规格；下面严格区分线上证据和尚未上板的推断。
原始证据文件及哈希见 `third-party.md`，可运行的抓包样例在 `tools/tests/test_ice.py`。

## 报文

设备标识为 VID `34BF`、PID `1002`；抓包里的 OUT/IN 为 64 字节。
hidapi API 写入时额外在首字节放报告 ID 0，故 API 缓冲为 65 字节。

```text
主机 OUT：FF 5A LEN CMD PAYLOAD CS [补零至 64 字节]
设备数据：LEN 02 DATA CS [补零至 64 字节]
设备事件：07 06 CONTENT[5] 04 [补零至 64 字节]
```

- OUT 的 LEN 包含 CMD、PAYLOAD、CS；有效部分所有字节的 sum8 为零。
- 数据回复 LEN 包含 02、DATA、CS；校验从 02 开始，不包含 LEN。
- 事件使用固定终止字节 04，不套用数据回复的校验算法。
- 单包读数据最多 61 字节，单包内存写最多 53 字节。
- 不使用删除尾零的处理；合法数据和补零通过 LEN 区分。

## 命令

| 命令 | 负载 | 用途 |
| --- | --- | --- |
| `00` | `00` | 查询版本，已见 `00 + ASCII V4.0` 事件 |
| `00` | `01` | 读取 46 字节 CPU 快照 |
| `00` | `02` | 暂停 |
| `04` | `space + addr32BE + count8` | 读内存 |
| `02` | `space + addr32BE + count8 + data` | 写内存 |
| `08` | `00` | 继续运行 |
| `08` | `01 + instruction[4] + 00` | 执行当前 PC 的一条指令 |

2026-11-15 的 V4.0 实机补充：已经暂停的目标可能不回复再次发送的 `00 02`。
当前实现等待暂停确认超时后，再发送 `00 01`；只有取得完整、长度与校验均正确的
46 字节 CPU 快照才返回成功，状态查询超时或格式错误仍报错。
该兼容处理已验证初始 `PC=FF0000` 和步进后的暂停状态。

HID 句柄打开后设置非阻塞模式。cython-hidapi 的 `read(size, 0)` 走默认读取模式，
不设置时会卡在发送前的旧事件轮询；正数超时仍按请求值执行限时读取。

CPU 快照和调试器虚拟地址映射见 `architecture.md`。
空间 0 的地址零、长度 4 为 PC 专用读取，不是普通 RAM 地址零。
空间 4 的 A8 对应 IE；空间 5 的代码写入用于 B9 软件断点。
空间 1/2 的普通 RAM 访问依赖驱动静态路径，仍待上板验证。
生产会话的 `read_memory()` 当前仍拒绝空间 5 的读取；代码窗口显式从本地 HEX 提供。
2026-11-15 后续静态核对确认，官方下载校验在 RVA `3172` 直接调用 `2D92(..., 5)`，
使用命令 04 回读设备代码，绕过 Keil 的本地缓存。独立诊断脚本的 `--verify-image`
已按该入口构造请求，尚待 V4.0 实机读回验收；详见 `usb-ice-diagnosis.md`。

## 单步与中断

请求中的四字节是当前 PC 处的代码窗口，不表示执行四字节。
真实抓包记录的七步为：

| 执行前 PC | 四字节窗口 | 执行后 PC |
| --- | --- | --- |
| FF0481 | C2 AF 7E 1F | FF0483 |
| FF0483 | 7E 1F 00 14 | FF0487 |
| FF0487 | 7A 1F 00 31 | FF048B |
| FF048B | 7E 73 00 30 | FF048F |
| FF048F | 2E 70 FF 92 | FF0492 |
| FF0492 | 92 AF 7E 1F | FF0494 |
| FF0494 | 7E 1F 00 31 | FF0498 |

`IceTarget.step()` 按驱动观察在单步前清 EA，并在确认停止后按需恢复。
当指令为 `C2 AF`（CLR EA）时不恢复，尊重用户指令的结果。
失败时不假定芯片已经停下，后续清理先请求暂停。
这会改变单步时的中断环境，不能据此推断外设在自由运行时的实时行为。

## 事件归属

运行请求可能有立即确认和稍后的停止事件，不能统一按“一发一收”实现。
首条回复归属当前命令；额外事件排队等待取出。
继续前清理上一轮暂停/断点操作的事件，避免立即误报停止。

全零的五字节内容可能表示确认，也可能表示停止，协议内没有序号。
因此仍存在迟到事件与当前确认无法完全区分的时序边界，必须上板复核。
格式、校验、长度错误或数据/事件类型不符会报错，不静默忽略。

## 与 stcgal 的边界

STCForge 的 USB 后端接受已经运行 ICE 驱动的设备。
ISP 下载、官方仿真固件自动装载和 ISP → ICE 切换由后续 stcgal 集成承担。
当前没有复位、PC 重定位或寄存器写回的可靠接口；这些命令不对 GDB 声称成功。
