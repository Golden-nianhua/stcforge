# SDCC USB-ICE 当前处理记录

更新：2026-11-16。下方2026-11-15记录为历史经过；其中临时补丁均已在后续恢复，不能当作当前待办。

## 最新状态

当前尚待恢复：同源 Keil 61 临时覆盖 `overlay-214254-358864` 出现暂停失联，USB-ICE 设备未枚举；2048字节备份未写回。未设置断点。恢复步骤及实码见[同源机器码对照](keil-sdcc-same-source-20261116.md)。原04完整示例的暂停/变量读取故障根因仍未定位，不能声称SDCC中断、EJMP或字节序已被证实有错。

保留原04功能及完整ISR的52（循环尾部18NOP）与54（同长度9个SJMP +0）均完成20轮真实GDB回归。但55正常C源码重编译的18NOP版本失败，说明简单插入NOP不是通用修复。详见同目录tail-window-and-fault-containment-20261116.md。

生产后端已修正首次USB通信错误后的处理：锁定首错、停止后续设备操作及断点写回、结束GDB会话，避免E01触发拆分读取并消费迟到回复。197项测试中196通过、1跳过；53实板故障也确认首错后停止发包。这是错误隔离修正，不是原始故障修复。

同一块板上，原04绕过GDB和hidapi，使用Win32原生HID也失败。进一步直接复用本机Keil官方DLL的运行、暂停、事件等待、PC读取和状态读取函数：03连续三轮通过，04收到暂停事件后在官方PC读取内等待超过12秒；外部诊断进程超时退出。该对照不等同完整Keil应用或ISP冷启动，但排除了GDB、hidapi、以及自写运行/暂停和第一笔PC读取实现作为这次故障的必要条件。记录见[官方驱动及等待周期对照](tail-window-and-fault-containment-20261116.md#官方驱动及等待周期对照)。

模板当前独立 SDCC Simulation Test 的 Debug 产物与04-split-only的HEX哈希一致，在原有GDB下20轮运行/暂停、变量、软件断点删除及单步全部通过（overlay-213855-642606）。这是可用的60000次有界等待版本，不含失败04新增的5ms超时。未测试实体UART输入，不把它当作通用修复。另对失败04原位替换32位比较、降系统时钟至24MHz以及改由Timer0执行原ISR，均仍失败；详情见[后续执行对照](tail-window-and-fault-containment-20261116.md#后续执行对照)。

M02_led_uart_timer 完整实板 PASS：1375 个代码字节前后核对一致，复位跳转单步、三轮全速运行与暂停、软件断点命中和删除、删除后单步均通过。

日志：模板 Misc/Simulation Firmware Matrix/logs/20261115-211847-792753-M02_led_uart_timer/result.json。

HEX 文件 SHA-256：242dc7332217845a4cf47972e1a7ae77927d43c51ed74d018cbe7b5e8da1874e。这里的 SHA 是原 M02 文件字节哈希；打包格式不同的等价 HEX 应按地址/代码字节比较。

该基线包含 P9.3 LED、UART7 轮询回显、Timer1 毫秒中断、XDATA 全局对象和 SPX 自动局部变量。没有证明全部 SDCC 程序均兼容 USB-ICE。

## 原例的根因边界

原 S00 和手动初始化 S06 均曾在全速运行后无法暂停。S06 已跳过自动 copy/clear，所以只把问题归因于 XINIT 不成立。外围初始化的主要机器码与 M02 相同；未找到可确认的非法 opcode、大小端或普通函数返回 ABI 错误。

将 S06 启动指令通过监控器的单步窗口逐条执行可抵达 main。该证据仅限单步执行，不能据此推断相同代码在全速运行时正常。

## 本轮临时探针与恢复状态

第一轮在完整核对过的 M02 上，临时改 FF00BF 的启动钩子返回值 01→00，并在 FF0497 设置 B9 软件断点。继续运行后句柄报 read error。重新打开 HID 后可读到 V4.0，两个字节均已恢复，1375 字节全镜像恢复核对通过。记录：.cache/m02-native-probe-recovery-20261115.jsonl。

第二轮只在原 M02 的 FF0497 设置 B9，先单步复位跳转，再运行，仍没有得到停止确认。因无修改启动钩子的基线也失败，第一轮不能证明自动运行库是根因。第二轮后版本查询亦超时，不能声称当前会话正常或断点已经恢复。

**待恢复的临时位置：FF0497，原值0B，探针值B9。** FF00BF 最后一次确认的原值是01。没有下载另一份固件或改 ISP 硬件选项。

重新给开发板上电后运行：

    & D:/Code/uv/uv.exe run --project D:/Projects/stcforge --no-sync python D:/Projects/stcforge/tools/diagnostics/recover_m02_probe.py
